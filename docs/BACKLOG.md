# Бэклог SNSocial

Что не вошло в v1.0 и почему. Приоритеты пересматриваются по фидбеку из чата поддержки.

## v1.1

- **Несколько каналов/групп на сеть.** Сейчас один ТГК + одна группа VK; сети под это
  спроектированы (`requires` уже список). Ждём реального запроса от серверов.
- **Сервисный ключ VK как fallback** для `groups.isMember`, если ключ сообщества словит
  ошибку прав (спека §5, кандидат «isMember ключом сообщества»).
- **`/snsocial stats`** — сколько привязок и подписок принёс плагин. Это же готовый пост
  для канала сервера («+N подписчиков за неделю»).
- **Настройки MySQL-пула** (размер, keepalive), если один worker-поток окажется узким
  местом на сетках.
- **Один бот на SNSocial + SNTelegram.** Telegram даёт токену только один getUpdates:
  два плагина линейки на одном сервере вынуждены заводить двух ботов (выяснилось на
  первом живом тесте 02.08.2026 — 409 Conflict с обеих сторон). Если SNTelegram
  установлен, SNSocial мог бы подписываться на его поток апдейтов вместо собственного
  опроса — один бот на всю линейку.

## v1.2

- **Discord** — для зарубежных сборок. В RU не приоритет: заблокирован с октября 2024.
- **Webhook-режим Telegram** вместо long polling — для тех, у кого есть домен и HTTPS.
- **`folia-supported: true`** — после реального теста на Folia (код уже на
  Folia-планировщиках, см. спеку §3.3).
- **`until_date` платных подписок Telegram** — если платные каналы станут кейсом.

## Осознанно не делаем

- **Проверка лайков/репостов/комментариев** — API нестабилен, боль не подтверждена,
  а фарм-абуз там неизлечим.
- **Свой пул соединений (HikariCP)** — шейдить библиотеку в чужой сервер ради нашей
  нагрузки «привязки и клеймы» незачем (правило №2 линейки).
- **Платные функции** — вся линейка SN бесплатная, это позиционирование, а не жест.
